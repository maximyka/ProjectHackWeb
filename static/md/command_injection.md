
### Что такое Command Injection?

**Command Injection (Внедрение команд ОС)** — это критическая уязвимость, позволяющая злоумышленнику выполнять произвольные команды операционной системы на сервере, где запущено приложение. Она возникает, когда приложение принимает пользовательский ввод и без должной очистки передает его в системную оболочку (shell) для выполнения.

### Как ею воспользоваться?

Злоумышленник использует специальные символы-разделители команд (`;`, `&&`, `|`, `||`), чтобы "прицепить" свою команду к легитимной команде сервера.

Типичный сценарий:

1. Приложение имеет функцию "проверить доступность узла" (ping), где пользователь вводит IP-адрес.
2. Вместо IP `8.8.8.8` злоумышленник вводит: `8.8.8.8; cat /etc/passwd`
3. Сервер отправляет в консоль команду: `ping -c 4 8.8.8.8; cat /etc/passwd`
4. ОС выполняет `ping`, а затем выполняет `cat /etc/passwd`, возвращая содержимое файла с паролями обратно пользователю.

### Что это дает злоумышленнику?

- ✓ **Remote Code Execution (RCE)** — Полный компрометирующий доступ к серверу (Remote Code Execution)
- ✓ Чтение, изменение и удаление любых файлов на сервере
- ✓ Установка бэкдоров и вредоносного ПО
- ✓ Разведка внутренней сети и продвижение (Lateral Movement)
- ✓ Превращение сервера в часть ботнета

### Где ошибка разработчика?

Разработчик вызывает системные утилиты напрямую и конкатенирует их с пользовательским вводом:

```python
# ❌ УЯЗВИМО
import os
from flask import request

@app.route('/network_test')
def network_test():
    ip = request.args.get('ip')
    # Ввод напрямую отдается в оболочку ОС
    result = os.popen(f"ping -c 4 {ip}").read()
    return f"<pre>{result}</pre>"
```

### Как это работает на уровне кода?

Когда код доходит до `os.popen()` с включенным шеллом, операционная система интерпретирует всю строку как Bash-скрипт (или CMD в Windows). Интерпретатор видит точку с запятой `;` и воспринимает её как конец первой команды и начало второй. В результате легитимный инструмент разработчика становится транспортом для вредоносного кода.

### Реальные истории взломов

**D-Link DSL Routers (CVE-2026-0625, CVE-2021-...)**

- Многие модели домашних роутеров имели встроенные утилиты для диагностики или настройки (например, эндпоинт `dnscfg.cgi`).
- Входные параметры не очищались должным образом, позволяя неаутентифицированным удаленным атакующим внедрять системные команды.
- Хакеры использовали разделители команд (например `| wget ...`) для загрузки и запуска вредоносных бинарных файлов (ботнет Mirai, TheMoon).

**Linksys E-Series (CVE-2025-34037)**

- Параметр `ttcp_ip` передавался напрямую в функцию выполнения команд (shell).
- Уязвимость использовалась червем "TheMoon", который распространялся автоматически по сетям, заражая устройства потребителей.

### Как защититься?

1. **Избегайте использования вызовов системной оболочки:** Используйте встроенные библиотеки языка программирования.
   
   ```python
   # ✅ БЕЗОПАСНО
   # Вместо вызова системного ping лучше использовать python-библиотеку для сети
   import socket
   try:
       socket.gethostbyname(ip)
       return "Host is valid"
   except socket.error:
       return "Invalid host"
   ```

2. **Используйте параметризованные функции выполнения:** Если системная команда неизбежна, передавайте аргументы в виде списка, запрещая использование shell.
   
   ```python
   # ✅ БЕЗОПАСНО
   import subprocess
   ip = request.args.get('ip')
   # shell=False гарантирует, что спецсимволы не будут интерпретироваться как команды
   result = subprocess.run(['ping', '-c', '4', ip], capture_output=True, text=True, shell=False)
   return result.stdout
   ```

3. **Строгая валидация ввода (Allow-list):** Использование регулярных выражений для проверки, что введен именно IP-адрес.
