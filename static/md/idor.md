### Что такое IDOR?

**IDOR (Insecure Direct Object Reference)** — это уязвимость контроля доступа, которая возникает, когда приложение предоставляет прямой доступ к объектам (файлам, записям базы данных, профилям) на основе пользовательского ввода без надлежащей проверки прав авторизации. Злоумышленник может просто изменить значение идентификатора (например, ID пользователя или номер документа) в запросе и получить доступ к чужим данным.

### Как ею воспользоваться?

Типичный сценарий:

1. Пользователь авторизуется в системе и запрашивает свой профиль или документ.
2. В URL-адресе или теле запроса передается идентификатор: `https://example.com/api/user/profile?id=1001`
3. Злоумышленник подменяет свой идентификатор на чужой: `https://example.com/api/user/profile?id=1002`
4. Сервер возвращает конфиденциальные данные пользователя с ID 1002, не проверяя, имеет ли текущий авторизованный пользователь права на просмотр этих данных.

**Другие примеры атак:**

- Модификация скрытых полей форм: `<input type="hidden" name="user_id" value="1001">` заменяется на `1002`.
- Перебор (brute-force) идентификаторов: использование автоматизированных скриптов для скачивания данных `id=1`, `id=2`, `id=3` и так далее (Enumaration).

### Что это дает злоумышленнику?

- ✓ Чтение чужой конфиденциальной информации (переписки, документы, финансовые данные)
- ✓ Горизонтальное повышение привилегий (доступ к аккаунту с такими же правами)
- ✓ Вертикальное повышение привилегий (модификация ID для изменения данных администратора)
- ✓ Массовая утечка (скрапинг) всей базы данных путем перебора ID
- ✓ Несанкционированное удаление или изменение чужих записей

### Где ошибка разработчика?

Разработчик доверяет пользовательскому вводу и использует его для поиска объекта в базе данных, забывая проверить, принадлежит ли объект тому, кто делает запрос.

```python
# ❌ УЯЗВИМО
@app.route('/document')
def get_document():
    doc_id = request.args.get('id')
    # Достаем документ, просто поверив переданному ID
    query = f"SELECT * FROM documents WHERE id = {doc_id}"
    doc = db.execute(query).fetchone()
    return doc.content
```

### Как это работает на уровне кода?

Сервер "думает" так: 
*"Пользователь просит документ номер 5. Я нашел документ номер 5 в базе. Вот он"*. 
Правильная логика должна быть такой: 
*"Пользователь просит документ номер 5. Я нашел его. Кто запрашивает? Пользователь A. А кто владелец документа 5? Пользователь B. Разрешено ли A читать документы B? Нет. В доступе отказано"*.

### Реальные истории взломов

**First American Financial Corp (2019)**

- Из-за уязвимости IDOR в веб-приложении компании в открытый доступ попало около **885 миллионов записей**.
- Любой человек, имея веб-браузер, мог просто менять цифры в URL-адресе документа и получать доступ к чужим файлам.
- Утекли: номера банковских счетов, номера социального страхования, сканы водительских прав и налоговые записи, начиная с 2003 года.

**Parler (2021)**

- Социальная сеть имела уязвимый API, где ID постов и файлов имели предсказуемую последовательность.
- Сервер не требовал авторизации и не ограничивал доступ.
- В результате исследователи (и злоумышленники) написали скрипт, который просто перебирал ID один за другим, что позволило выкачать терабайты данных (включая удаленные посты и геолокацию видео).

### Как защититься?

1. **Проверка прав доступа (Authorization Check):**
   
   ```python
   # ✅ БЕЗОПАСНО
   @app.route('/document')
   def get_document():
       doc_id = request.args.get('id')
       current_user_id = session.get('user_id')
   
       # Запрашиваем документ только если он принадлежит текущему пользователю
       query = "SELECT * FROM documents WHERE id = ? AND owner_id = ?"
       doc = db.execute(query, (doc_id, current_user_id)).fetchone()
   
       if not doc:
           abort(403) # Доступ запрещен или файл не найден
       return doc.content
   ```

2. **Использование косвенных ссылок или UUID:** 
   Вместо предсказуемых целочисленных ID (например, `id=5`) используйте случайно сгенерированные и непредсказуемые UUID (например, `id=a3f9c2d1-...`). Это предотвратит перебор, хотя и не заменит полноценную проверку прав доступа.
