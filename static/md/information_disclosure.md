
### Что такое Information Disclosure?

**Раскрытие информации (Information Disclosure / Sensitive Data Exposure)** — это проблема безопасности, при которой веб-приложение непреднамеренно раскрывает конфиденциальную информацию пользователям. Это могут быть технические детали (стек-трейсы, версии ПО, API ключи), которые помогают хакерам спланировать более сложную атаку, или напрямую личные/бизнес данные.

### Как ею воспользоваться?

1. **Анализ исходного кода страницы:** Поиск скрытых комментариев HTML (`<!-- TODO: убрать пароль БД admin:qwerty -->`).
2. **Провоцирование ошибок:** Ввод неверных данных (например, буквы вместо цифр), чтобы сервер упал и вернул Stack Trace (отладочный отчет с путями к файлам и версиями библиотек).
3. **Обнаружение публичных файлов конфигурации:** Обращение к стандартным директориям, например, `/.git/`, `/.env`, `/backup.zip`, `/phpinfo.php`.

### Что это дает злоумышленнику?

- ✓ Сбор информации для проведения адресных атак (Reconnaissance)
- ✓ Получение API-ключей к сторонним сервисам (AWS, платежные шлюзы)
- ✓ Доступ к исходному коду приложения (при утечке папки `.git`)
- ✓ Утечка базы данных (если сливаются учетные данные)

### Где ошибка разработчика?

Разработчик оставляет приложение в режиме отладки (debug mode) в рабочей среде (production) или случайно публикует секретные файлы в публичном доступе.

```python
# ❌ УЯЗВИМО
from flask import Flask
app = Flask(__name__)

@app.route('/profile/<int:user_id>')
def profile(user_id):
    # Если передать строку вместо числа, Flask выбросит подробную ошибку со всем стеком
    user = get_user(user_id) 
    return user.name

if __name__ == '__main__':
    # Ошибка: Режим отладки оставлен включенным!
    app.run(debug=True)
```

### Как это работает на уровне кода?

При возникновении исключения (Exception), фреймворк (в режиме Debug) перехватывает ошибку и вместо скучного "500 Internal Server Error" генерирует красивую интерактивную страницу. Эта страница содержит строки кода, локальные переменные, пути файловой системы и версии модулей. Для хакера — это карта сокровищ.

### Реальные истории взломов

**Uber (2016)**

- Разработчики Uber случайно опубликовали закрытые ключи от инфраструктуры Amazon Web Services (AWS) в публичном репозитории на GitHub.
- Злоумышленники нашли эти ключи, авторизовались в AWS и скачали конфиденциальные данные **57 миллионов пользователей** и 600,000 водителей.
- Uber заплатил хакерам $100,000 за молчание, скрывая взлом, что позже вылилось в огромные судебные иски.

**NASA Jet Propulsion Lab (2018)**

- Сервер Jenkins, используемый NASA, был неверно сконфигурирован, что открыло публичный доступ к внутренним сценариям развертывания и логам сборки.
- Это раскрыло учетные данные и детали конфигурации проектов, потенциально ставя под угрозу космические миссии.

### Как защититься?

1. **Отключение режима отладки в Production:**
   
   ```python
   # ✅ БЕЗОПАСНО
   if __name__ == '__main__':
       app.run(debug=False)
   ```

2. **Обработка исключений и кастомные страницы ошибок:**
   
   ```python
   @app.errorhandler(500)
   def internal_error(error):
       # Логируем реальную ошибку в безопасный внутренний файл
       app.logger.error(f"Server Error: {error}")
       # Пользователю отдаем обобщенное сообщение
       return "Произошла непредвиденная ошибка", 500
   ```

3. **Секреты в переменных окружения:** Никогда не хранить пароли в коде (использовать менеджеры секретов).

4. **Конфигурация веб-сервера:** Отключить листинг директорий (`Options -Indexes` в Apache) и заблокировать доступ к `.env` и `.git` файлам.
