### Что такое Open Redirect?

**Open Redirect** — это уязвимость, возникающая, когда веб-приложение принимает контролируемый пользователем ввод (часто из параметров URL) и использует его для перенаправления (редиректа) браузера на другой адрес без валидации. Это позволяет злоумышленнику использовать доверенный домен сайта для перенаправления жертвы на вредоносный ресурс.

### Как ею воспользоваться?

Типичный сценарий:

1. Приложение имеет механизм авторизации, который возвращает пользователя на исходную страницу после логина: `https://trusted.com/login?next=/dashboard`
2. Злоумышленник формирует фишинговую ссылку: `https://trusted.com/login?next=http://evil-phishing.com`
3. Злоумышленник отправляет эту ссылку жертве.
4. Жертва видит, что ссылка начинается с `trusted.com` и доверяет ей.
5. После входа в систему сервер выполняет перенаправление, и жертва оказывается на сайте злоумышленника, который может выглядеть в точности как оригинал, чтобы выманить повторный ввод пароля или данные карты.

### Что это дает злоумышленнику?

- ✓ Мощный инструмент для фишинга (повышение доверия жертвы)
- ✓ Кража токенов OAuth (путем подмены `redirect_uri`)
- ✓ Обход фильтров безопасности (например, антиспам-системы видят легитимный корневой домен)
- ✓ Удар по репутации доверенной компании

### Где ошибка разработчика?

Разработчик берет параметр из запроса и подставляет его прямо в HTTP-заголовок `Location` или в функцию редиректа фреймворка:

```python
# ❌ УЯЗВИМО
from flask import request, redirect

@app.route('/login', methods=['POST'])
def login():
    # ... логика проверки пароля ...
    target_url = request.args.get('next')
    # Слепо доверяем параметру 'next'
    return redirect(target_url)
```

### Как это работает на уровне кода?

Приложение формирует HTTP-ответ со статусом 302 Found (или 301). В заголовке `Location` указывается адрес, на который должен перейти браузер. Если этот адрес полностью контролируется пользователем, браузер послушно уходит на чужой домен.

### Реальные истории взломов

**Tumblr (2024)**

- В механизме выхода из системы (logout) социальной сети Tumblr исследователи безопасности нашли Open Redirect.
- Сервер не проверял параметр, отвечающий за страницу, на которую перейдет пользователь после выхода.
- Хакеры могли использовать это для создания ссылок на доменах Tumblr, которые фактически вели на мошеннические сайты.

**Кража токенов OAuth (Различные программы Bug Bounty)**

- Во многих атаках на SSO (Single Sign-On) платформы злоумышленники используют Open Redirect. 
- Пользователь авторизуется в легитимном сервисе (например, через Google или Facebook), но параметр `redirect_uri` модифицируется. В итоге секретный токен доступа отправляется на сервер злоумышленника.

### Как защититься?

1. **Использование белого списка (Allow-list):**
   
   ```python
   # ✅ БЕЗОПАСНО
   ALLOWED_URLS = ['/dashboard', '/profile', '/settings']
   target_url = request.args.get('next')
   if target_url not in ALLOWED_URLS:
       target_url = '/dashboard' # Дефолтное значение
   return redirect(target_url)
   ```

2. **Валидация относительных путей:** Разрешать перенаправление только внутри своего домена (убедившись, что путь начинается с одного `/`, а не с `//` или `http`).
   
   ```python
   # ✅ БЕЗОПАСНО
   from urllib.parse import urlparse
   
   target_url = request.args.get('next')
   parsed = urlparse(target_url)
   # Если host пустой - значит это локальный относительный путь
   if parsed.netloc == '' and parsed.scheme == '':
       return redirect(target_url)
   return redirect('/')
   ```
