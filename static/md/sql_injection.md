## SQL INJECTION (SQL-инъекция)

### Что такое SQL Injection?

**SQL Injection** — это уязвимость веб-приложения, которая позволяет злоумышленнику внедрять вредоносный код SQL в параметры приложения. Если приложение напрямую использует пользовательский ввод в SQL-запросах без надлежащей валидации и экранирования, злоумышленник может изменить логику запроса и выполнить несанкционированные операции с базой данных.

### Как ею воспользоваться?

Типичный сценарий:
1. Веб-приложение имеет форму входа, которая проверяет учетные данные пользователя в базе данных
2. Вместо обычного пароля, злоумышленник вводит специальную строку: `' OR '1'='1`
3. SQL-запрос становится: `SELECT * FROM users WHERE username='admin' AND password='' OR '1'='1'`
4. Поскольку условие `'1'='1'` всегда истинно, запрос возвращает всех пользователей, и условие логин пропускается

**Другие примеры атак:**
- Извлечение данных из других таблиц: `' UNION SELECT username, password FROM users --`
- Удаление данных: `'; DROP TABLE users; --`
- Изменение данных: `'; UPDATE users SET role='admin' WHERE id=1; --`

### Что это дает злоумышленнику?

- ✓ Обход аутентификации (вход без пароля)
- ✓ Кража конфиденциальной информации (пароли, номера кредитных карт, личные данные)
- ✓ Модификация или удаление данных
- ✓ Получение доступа к административным функциям
- ✓ В некоторых случаях — удаленное выполнение кода на сервере

### Где ошибка разработчика?

Разработчик напрямую конкатенирует пользовательский ввод в SQL-запрос:

```python
# УЯЗВИМО
username = request.form['username']
password = request.form['password']
query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'"
result = db.execute(query)
```

Пользовательский ввод не валидируется и не экранируется, поэтому специальные символы (кавычки, точки с запятой) интерпретируются как часть SQL-кода.

### Как это работает на уровне кода?

Когда нормальный пользователь входит с именем `admin` и паролем `secret`, запрос выглядит так:
```sql
SELECT * FROM users WHERE username='admin' AND password='secret'
```

Но если злоумышленник вводит пароль `' OR '1'='1`, запрос становится:
```sql
SELECT * FROM users WHERE username='admin' AND password='' OR '1'='1'
```

SQL-интерпретатор видит два условия:
1. `username='admin' AND password=''` — ложь (пароль пуст)
2. `OR '1'='1'` — всегда истина

Итоговое условие: ложь OR истина = **истина**, поэтому запрос возвращает пользователя.

### Реальные истории взломов

**Yahoo! Voices (2012)**
- Хакеры использовали SQL Injection для компрометации веб-приложения Yahoo! Voices
- Украдены данные **450,000 пользователей**: логины, пароли и адреса электронной почты
- Данные хранились в открытом виде без хеширования
- Взлом произошел через уязвимый параметр в URL, где приложение конкатенировало пользовательский ввод

**TalkTalk (2015)**
- Британская телекоммуникационная компания подверглась SQL Injection атаке
- Компрометированы данные **156,959 клиентов**
- Украдены: имена, адреса, номера телефонов, сортировочные коды банков
- Данные передавались в открытом виде через интернет
- Компания заплатила штраф в размере £400,000

**Adobe Systems (2013)**
- Взломаны серверы компании через SQL Injection
- Украдены данные **3 млн пользователей**
- Компрометированы пароли, номера кредитных карт, номера социального страхования
- Внутреннее расследование выявило, что уязвимость существовала несколько лет

### Как защититься?

1. **Подготовленные запросы (Prepared Statements):**
```python
# БЕЗОПАСНО
query = "SELECT * FROM users WHERE username=? AND password=?"
result = db.execute(query, (username, password))
```

2. **Экранирование специальных символов:** использование функций экранирования БД

3. **ORM (Object-Relational Mapping):** использование фреймворков типа SQLAlchemy, которые автоматически экранируют ввод

4. **Принцип наименьших привилегий:** пользователь БД должен иметь минимально необходимые права

5. **Валидация ввода:** проверка типов данных, формата и длины
