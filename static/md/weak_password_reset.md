
### Что такое Weak Password Reset?

**Weak Password Reset** — это категория логических уязвимостей, связанных с процессом восстановления забытого пароля. Самый опасный и частый вектор — **Host Header Injection** (Инъекция заголовка Host). Она возникает, когда сервер доверяет заголовку `Host` из запроса клиента для формирования ссылки на сброс пароля, отправляемой на email жертвы.

### Как ею воспользоваться?

Атака "Отравление сброса пароля" (Password Reset Poisoning):

1. Злоумышленник знает email жертвы.
2. Он инициирует сброс пароля на сайте через прокси-инструмент (Burp Suite).
3. В HTTP-запросе он изменяет заголовок: `Host: target.com` на `Host: evil-hacker.com`.
4. Сервер принимает запрос, генерирует секретный токен для жертвы и формирует ссылку, используя переданный Host.
5. Жертва получает официальное письмо от сайта с текстом: *"Чтобы сбросить пароль, перейдите по ссылке: https://evil-hacker.com/reset?token=12345XYZ"*.
6. Если жертва кликнет по ссылке (или ее проверит антивирус), секретный токен утечет на сервер хакера.
7. Хакер берет токен, заходит на реальный `target.com` и меняет пароль жертвы на свой.

### Что это дает злоумышленнику?

- ✓ Account Takeover (ATO) — Полный захват аккаунта жертвы (вплоть до аккаунта администратора)
- ✓ Компрометация корпоративной почты или финансовых счетов
- ✓ Обход двухфакторной аутентификации (в некоторых кривых реализациях)

### Где ошибка разработчика?

Разработчик хочет сделать код "динамическим" и независимым от окружения, поэтому берет домен для ссылки прямо из HTTP-запроса клиента:

```python
# ❌ УЯЗВИМО
@app.route('/forgot-password', methods=['POST'])
def forgot_password():
    email = request.form['email']
    user = get_user(email)
    token = generate_secure_token(user)

    # Использование request.host для построения ссылки - фатальная ошибка
    reset_link = f"https://{request.host}/reset?token={token}"

    send_email(user.email, f"Сброс пароля: {reset_link}")
    return "Ссылка отправлена"
```

### Как это работает на уровне кода?

HTTP-заголовок `Host` является частью запроса клиента, а значит, он полностью контролируется пользователем. Веб-сервер передает этот заголовок приложению (во Flask это `request.host`, в PHP это `$_SERVER['HTTP_HOST']`). Поскольку приложение не имеет жестко заданного собственного домена, оно берет поддельный домен хакера и вставляет его в письмо.

### Реальные истории взломов

**Silverstripe CMS (2021)**

- Популярная система управления контентом формировала ссылки для сброса пароля на основе заголовка Host.
- Во время масштабного сканирования в 2021 году выяснилось, что тысячи сайтов уязвимы. 
- Более того, почтовые серверы (такие как Microsoft Office 365) с функцией "SafeLinks" автоматически переходили по ссылкам в письмах для проверки их на вирусы, невольно отправляя секретные токены на сервер злоумышленника без всякого участия пользователя (Zero-Click).

**Отчеты Bug Bounty (например, Mavenlink 2017)**

- Исследователи массово находили эту уязвимость у крупных компаний. Подменяя заголовок Host на свой домен или субдомен, хакер заставлял сервер формировать валидные письма, позволяющие "угонять" учетные записи.

**Instagram (2015 - другой тип слабого сброса)**

- В Instagram был обнаружен изъян в сбросе пароля: 6-значный код восстановления, отправляемый на телефон, не имел ограничения на количество попыток (Rate Limiting). Хакер мог запросить код и за несколько минут подобрать нужную комбинацию от 000000 до 999999, взломав любой аккаунт.

### Как защититься?

1. **Жестко заданный базовый URL (Base URL):**
   Никогда не доверяйте заголовку `Host`. Храните доменное имя вашего сайта в защищенном конфигурационном файле на сервере.
   
   ```python
   # ✅ БЕЗОПАСНО
   # Задаем в конфигурационном файле (config.py): BASE_URL = 'https://polygon-site.com'
   
   @app.route('/forgot-password', methods=['POST'])
   def forgot_password():
       user = get_user(request.form['email'])
       token = generate_secure_token(user)
   
       # Берем безопасный URL из конфигурации сервера
       reset_link = f"{app.config['BASE_URL']}/reset?token={token}"
       send_email(user.email, f"Сброс пароля: {reset_link}")
   ```

2. **Проверка заголовка Host на уровне веб-сервера:**
   Настройте Nginx или Apache так, чтобы они отклоняли запросы с нераспознанными или подмененными заголовками Host, возвращая ошибку 400 Bad Request.

3. **Ограничение скорости (Rate Limiting):**
   Обязательно ограничивайте количество запросов на сброс пароля и ввод кодов подтверждения.
